# 05 — User interface

Three surfaces: tray menu (always visible), transient windows (inbox, tag sheet, settings, first-run), and macOS notifications. The app has no main window and no dock icon (`LSUIElement=true` in `Info.plist`).

## 5.1 Tray menu

The `menubar` npm package gives us a tray icon plus an anchored popover. In v1 we use a classic Electron menu (`Menu.buildFromTemplate`) rather than a custom popover — simpler, looks native, and nothing here needs rich layout.

### Icon state

| State | Icon |
|---|---|
| Idle | `tray-idle` (template image) |
| Polling | `tray-polling` for ~2s during a poll, then back to idle |
| Processing | `tray-processing` while pipeline running |
| Error present | `tray-error` (persists until errors are cleared) |

Badge text (next to the icon) shows inbox count if >0: "●3". Use NSStatusItem title attribute; macOS Tahoe 26 renders this cleanly.

### Menu template

```
┌──────────────────────────────────────────┐
│ Status: Last sync 2m ago · 3 in inbox    │  (informational, disabled item)
│──────────────────────────────────────────│
│ Inbox (3)…                               │  → opens inbox window
│ Recent                            ▸      │  → submenu: last 5 completed recordings
│──────────────────────────────────────────│
│ Sync now                                 │  → immediate poll
│ Pause polling                            │  → toggles to "Resume polling"
│──────────────────────────────────────────│
│ Updates (1) …                            │  → opens Updates window if suggestions pending
│ Prompt suggestions (2) …                 │  → opens Suggestions window if pending
│ Errors (1) …                             │  → opens Errors window if any
│──────────────────────────────────────────│
│ Settings…                                │
│ About distill                        │
│ Quit                                     │
└──────────────────────────────────────────┘
```

Rules:
- The three "(N)" items are only shown when N > 0. Otherwise hidden.
- "Recent" submenu entries show `{client} — {meeting type} — {HH:mm}` and open the Apple Note on click (via `open "notes://…"` URL or a fallback to activating Notes).
- "Sync now" is a manual trigger; disabled while a poll is in flight.
- The informational status line uses a `disabled` menu item with styled text. Updates live every 30s while the menu is open.

## 5.2 Inbox window

Opens as a compact `BrowserWindow` (no titlebar chrome beyond the close button), ~480×640px, positioned under the tray icon. Renders a React view.

List of recordings with `status='inbox'`, newest first. Each row:

```
┌───────────────────────────────────────────────────────┐
│ Workshop recording 09-Apr.mp3                         │
│ Today 14:30 · 52m 14s                                 │
│ [ Tag & process ]   [ Skip ]   [ Play ▷ ]            │
└───────────────────────────────────────────────────────┘
```

- "Tag & process" → opens tag sheet (5.3).
- "Skip" → sets `status='skipped'`, confirms with a subtle toast.
- "Play ▷" → plays the cached MP3 if already downloaded, else streams from the Plaud temp URL. Useful when the filename isn't obvious.

Footer: "N recordings in inbox · Show skipped" toggle.

Empty state: "No recordings in inbox. New recordings will appear here when they sync from Plaud."

## 5.3 Tag sheet

A small modal (~420×360px) opened from the inbox. Fields:

- **Client**: combobox (searchable dropdown). Items: all clients ordered by `sort_order`, `name`. Last item: "`+ Add new client…`" — reveals an inline input + "Add" button. Validation: non-empty, unique.
- **Meeting type**: combobox. Items: all meeting types. Last item: "`+ Add new meeting type…`" — opens a larger panel with name input and prompt textarea (Markdown, monospace, ~16 lines visible). Validation: non-empty name, unique, non-empty prompt.
- **Note title**: optional override of the default template. Defaults to the meeting type's `note_title_template` or the global default.

Buttons: `Save & process` (primary), `Cancel`.

On save:
- Persist the recording's `client_id` and `meeting_type_id`.
- If a new client or meeting type was added, insert it first, then reference it.
- Set `status='tagged'`.
- Enqueue on the pipeline worker.
- Close the sheet; return focus to the inbox.

Keyboard shortcuts: `⌘↩` saves, `Esc` cancels, `⌘K` focuses the client combobox.

## 5.4 Settings window

A standard `BrowserWindow`, ~800×600px, resizable, with a sidebar + content layout.

Sidebar sections:

- **General** — poll interval slider, pause toggle, log level, startup behaviour (LaunchAgent install/uninstall button).
- **API keys** — Anthropic (masked input, "Test" button that makes a small `claude-3-5-haiku` call), HuggingFace (masked, "Test" button that lists pyannote's cached models), Plaud (shows logged-in email + "Log out" / "Sign in again").
- **Clients** — table of clients. Add / edit / delete. "Delete" is disabled for `Unclassified` and warns if the client has any recordings (offers reassignment to another client).
- **Meeting types** — list of meeting types, each expanding to a prompt editor. Shows prompt version history with diffs, the ability to rollback to a prior version, and a "Suggested improvements" badge if any pending `prompt_suggestions` exist for the type.
- **Transcription** — Whisper model selector (populated from installed mlx-community models + a "Download another…" option that kicks off model download), language override, diarisation on/off, min/max speakers.
- **Notes** — parent folder name, account (iCloud vs On My Mac), title template, Markdown backup on/off and base dir.
- **Updates** — list of pending model suggestions with release notes, accept/dismiss buttons, rollback history. See `06-self-maintaining.md`.
- **Storage** — disk usage (audio cache, Python venv, SQLite), purge controls, audio retention days.
- **About** — version, links to docs / repo / Anthropic docs / pyannote docs.

All Settings changes are saved on input (no global "Save" button) — standard macOS pattern.

## 5.5 Suggestions windows (Updates + Prompt Suggestions)

Two focused windows, opened from their tray entries.

### Updates window

Each pending `model_suggestions` row renders as a card:

```
┌────────────────────────────────────────────────┐
│ Claude — new model available                   │
│ Current:  claude-sonnet-4-6                    │
│ Proposed: claude-sonnet-4-8                    │
│ Released: 2 Apr 2026                           │
│ Notes: Better at structured outputs, same      │
│ pricing, same context window.                  │
│                                                 │
│ [ Switch ]   [ Dismiss ]   [ Compare on 1 note ]│
└────────────────────────────────────────────────┘
```

"Compare on 1 note" reruns the most recent complete recording through the proposed model and shows the two summaries side-by-side. Doesn't change the live config. See `06-self-maintaining.md` for the comparison flow.

### Prompt Suggestions window

Each pending `prompt_suggestions` row renders as a card with:

- Meeting type it applies to
- Rationale (Claude's explanation of what it noticed)
- Side-by-side diff of current vs proposed prompt, with changes highlighted
- List of the recordings that informed the suggestion (clickable → opens the Apple Note)
- Buttons: `Accept as-is`, `Edit & accept`, `Dismiss`

"Edit & accept" opens the prompt in an editor pre-filled with the proposal; user tweaks, saves. That becomes the new prompt; `prompt_suggestions.status='edited'`, a new `prompt_history` row is created with `reason='accepted-suggestion'`.

## 5.6 Rating a completed note

From the Recent submenu or the Apple Note's companion view (if we add one in v1.1), each completed recording has a thumbs-up / thumbs-down control.

The rating is stored on `recordings.rating`. Thumbs-down opens a tiny prompt: "What was missing or wrong? (optional)" — free text to `rating_comment`.

Ratings feed the reflection job (see `06-self-maintaining.md`).

Because v1 has no in-app view of the completed summary (it lives in Apple Notes), the rating UI can surface either:
1. As a native notification action on the "Processing complete" notification ("👍" / "👎" buttons), or
2. As a small item in the tray's Recent submenu that opens a rating sheet.

Pick (1) if notification actions are reliable on current macOS; (2) otherwise. **Verify** at build time.

## 5.7 First-run window

Opens once, full-screen modal feel, five pages:

1. **Welcome** — what the app does in 3 bullets; link to docs.
2. **Anthropic API key** — input + "Get a key" link to console.anthropic.com.
3. **HuggingFace token** — input + "Get a token" link, plus an explicit step to click "Accept licence" on the two pyannote model pages (with direct links and a "I've accepted" checkbox).
4. **Plaud account** — if `@plaud/core` already has a saved token, skip; otherwise email + password input, uses `PlaudAuth.login()`.
5. **Download models** — Python bootstrap progress (uv install, venv creation, dependency install, Whisper model download, pyannote model download). Shows real-time progress per step. This page can take 5–15 minutes on a fresh machine over a good connection.

Final page: "Install at login?" toggle (default on) → writes the LaunchAgent plist. "Finish" closes the wizard.

The wizard uses the same `BrowserWindow` style as Settings but with a linear stepper and disabled back-navigation once a step is committed.

## 5.8 Accessibility

- All interactive elements need keyboard navigation.
- macOS `NSStatusItem` is screen-reader-accessible via its title; keep the title meaningful ("distill · 3 in inbox" rather than just an icon).
- Inbox and Settings lists: arrow-key navigation, `Return` activates primary action.
- Colour is never the sole signal — tray-error also changes the icon shape, not just tint.
